# Go React-only: retire Angular across the mfe-pot family

## Status (2026-08-06): done

All 5 frontends are React. Angular has been removed entirely — not kept as a fallback, not left half-converted anywhere. `mfe-pot-platform`'s shared libraries, root dependencies, Renovate preset, and `CLAUDE.md` have all been cleaned up to match. This doc is the durable record of how the migration was planned and how it actually went; `mfe-pot-platform/CLAUDE.md` is the living architecture reference for the resulting React-based system — read that one for "how does this work today," this one for "why does it work this way, and what did it take."

## Why

Before this migration, `mfe-pot` was framed as "a PoT demonstrating Angular micro-frontend architecture," with 4 of 5 frontends Angular and one (`job-bank`) React — a deliberate earlier experiment to prove Native Federation could host a mixed-framework family. Getting job-bank working alongside four Angular apps surfaced three real production bugs plus a genuine upstream `@angular-architects/native-federation` bug requiring a `pnpm patch`. Weighing that cost against Angular's own DI/EnvironmentInjector-heavy federation-hosting code (a whole `REACT_MOUNTER`/`ViewContainerRef` mounting layer that only existed because Angular couldn't host a React tree directly) led to the decision to go the other way entirely: make every app React, and delete Angular rather than keep paying the mixed-framework tax indefinitely.

Two rounds of research (Explore/Plan agents plus direct inspection of `remote-route-host.ts`/`widget-loader.types.ts`) grounded the plan in the actual code, not generic migration advice. The core finding that shaped everything downstream: the federation layer had already half-anticipated this. `RemoteRouteHost` already branched on `remoteKind: 'angular' | 'react'`; `WidgetLoader`'s `LoadedReactWidget` type already had no `providers` field, because job-bank's presence had already proven remotes could be fully self-configuring instead of receiving injected DI providers from a host. The migration didn't invent a new composition model — it finished the one job-bank's presence had already started, then deleted the Angular half once nothing needed it.

## Sequencing

Order: **tag current state → platform infra → shell → employment-life-events → employment-insurance → dashboard → final cleanup**, smallest-first by relative effort, except platform infra and shell which had to come before everything else regardless of size (platform infra because every app's federation-runtime/i18n dependency had to exist first; shell because it's the one place `RemoteRouteHost` is actually consumed, so nothing else could prove its own conversion worked until shell could host it).

A `pre-react-migration` annotated tag was pushed to all 7 repos (the 5 apps, the platform repo, and this meta repo) before any code changed, specifically so there was a clean rollback point — requested explicitly, not a default practice for every change in this codebase.

## What actually happened, phase by phase

**Phase 0 — platform infra** (`mfe-pot-platform`): `shared-federation-runtime` and `shared-i18n` rewritten from scratch as React packages (new majors: `1.0.x`/`1.0.0`), old Angular-DI-shaped `0.x` majors kept published for not-yet-converted apps to pin during the transition. `widget-loader.types.ts` collapsed from a `kind`-discriminated union with Angular-only `providers` to a single `{component}` shape. A GCDS-direct-in-React spike confirmed no Angular wrapper layer was needed at all — every app now renders `@gcds-core/components`'/`shared-ui-scds-core`'s custom elements directly via JSX.

**Phase 1 — shell**: the highest-risk phase despite being one of the smaller apps by file count, because it's the one place `RemoteRouteHost` actually mounts a remote, the one place GCDS-direct-consumption got proven for real, and the first Angular→React *build-tooling* conversion in the family (job-bank never had to convert away from an Angular executor — it started on hand-written `esbuild` scripts). Took six rounds of live-browser-driven bug fixes, including the single hardest-won lesson of the whole migration: the classic-vs-automatic JSX transform split (`jsxFactory: React.createElement` required for anything bundled as a federation-shared/exposed chunk, since `react/jsx-runtime` can't resolve once federation-shared — confirmed against a real federated mount, not just a failing build). Also landed here: the real PKCE sign-in flow (ported near-verbatim from the pre-existing `mock-idp` work, framework-agnostic from the start) and the native-import-map-vs-`shimMode` fix (`setImportMapFn`/`hostRemoteEntry`).

**Phase 2 — employment-life-events**: smoothest phase, verified clean on essentially the first pass, because the JSX-transform and build-tooling lessons from Phase 1 were applied proactively rather than rediscovered. `PAYMENT_HISTORY_WIDGET_LOADER` consumption genuinely simplified from `inject(...) + createEnvironmentInjector` to a plain hook call rendering whatever component it resolves to.

**Phase 3 — employment-insurance**: 4 Angular feature libs folded into flat `apps/employment-insurance/src/app/*.tsx` components — the pattern every subsequent phase (and, retroactively, the understanding of why job-bank was always shaped this way) confirmed as the family's new default, replacing the Angular-era "apps are thin, `libs/<name>/feature-*` holds the logic" split. `ReportingStatus.tsx` became the one real consumer of `shared-i18n`'s `{{param}}` interpolation. One live-debugging false alarm worth remembering: `scds-card`'s `description`/`tone` props appeared missing from `outerHTML`/`getAttribute()` after a real BFF round-trip, which looked exactly like a rendering bug — turned out `reflect: false` Stencil props never show up as DOM attributes even when they render correctly via React's property-assignment path; the live shadow DOM confirmed the content was right all along.

**Phase 4 — dashboard**: the last and largest app, and the first point full composed-system verification (all apps live together, real cross-widget data) was even possible, since `Overview.tsx` is both a widget *source* (`./PaymentHistoryWidget`) and a widget *consumer* (job-bank's and employment-insurance's widgets) simultaneously. Live-verifying this phase surfaced a genuinely new, independent bug — not a dashboard bug at all: `mfe-pot-shell`'s own `build.mjs`/`serve.mjs` had only ever marked `react`/`react-dom` `external` in the plain-`esbuild` bundle for `main.tsx`, never `@tn4consulting/shared-federation-runtime`. That silently inlined a second, disconnected copy of the widget-loader Context objects into shell's own bundle — every cross-remote widget had been rendering its "unavailable" fallback with zero console error since Phase 1, indistinguishable from a genuinely unreachable remote, and nothing before Phase 4 had ever exercised two live widget Contexts with real remotes on both ends at once to surface it. Fixed in `mfe-pot-shell` directly (see that repo's own commit history); confirmed fixed via a real browser showing the EI reporting-status widget's actual status card and the job-applications widget's real (empty) state, both through the shell with full GC branding.

**Phase 5 — final cleanup**: `libs/shared/ui-gcds` (Angular `MscaAppFrame` wrapper) and `libs/shared/ui-scds` (Angular ng-packagr wrapper around `ui-scds-core`) deleted outright — zero consumers left anywhere in the family, confirmed by grep across all 6 repos before deleting, not assumed. `libs/shared/auth`'s orphaned `requireSessionGuard` (Angular Router-specific, replaced by a React Router `RequireSession` component back in Phase 1) deleted. `libs/shared/federation-config`'s Angular-shaped `index.js` deleted — `react.js`'s pattern is now the package's only export. Root `package.json`, `platform-versions.json`, and the shared Renovate preset (`default.json`) all had every Angular/RxJS/Transloco/GCDS-Angular-wrapper trace removed, replaced where relevant with React/GCDS-Angular's actual successor tracking. `CLAUDE.md` rewritten throughout — the platform repo's and all 5 app repos' — to describe the React architecture as it exists today rather than the Angular one it replaced, including a full "Federation" section rewrite covering `React.lazy`/`Suspense` mounting and Context-based cross-remote widget loading in place of `REMOTE_PROVIDERS`/`EnvironmentInjector`.

## What's deliberately not done

- **Old Angular-shaped package majors stay published on GitHub Packages** (`shared-federation-runtime@0.3.0`, `shared-i18n@0.1.x`, plus whatever version `shared-ui-gcds`/`shared-ui-scds` last published at) — nothing in the family depends on them anymore, but unpublishing/deprecating them is a registry action, more disruptive and harder to reverse than a repo change, and wasn't done unilaterally as part of this cleanup.
- **`shared-locale-sync` was flagged as now-pointless indirection, not yet acted on.** It was split out of `shared-i18n` specifically so a non-Angular remote could use locale sync without pulling in Angular/Transloco through that package's barrel export. Now that Transloco is gone from the family entirely, `shared-i18n` is already 100% framework-agnostic, and the split buys nothing anymore — folding it back in would remove one published package and one dependency line from 4 of 5 app repos. Real, low-risk simplification; deliberately left as a follow-up rather than bundled into this migration's own scope.
- **`shared-auth`'s `/core` vs root export split is now redundant** (both exports are byte-identical since `requireSessionGuard` was deleted) but wasn't collapsed — doing so means touching an import line in all 5 app repos for zero behavior change, lower value than the `shared-locale-sync` fold above.
- **job-bank's own local `use-locale.ts`/`use-translations.ts` hooks were never reconciled onto the shared `shared-i18n` package** — job-bank predates that package (its pattern is what `shared-i18n`'s hooks were modeled on, not the reverse), and its local version doesn't support `{{param}}` interpolation. Not part of this migration's scope (job-bank was never Angular), flagged in that repo's own `CLAUDE.md` as a separate, smaller cleanup.
- **Native Federation itself was not reconsidered as a runtime**, despite having been chosen partly "to match Angular's esbuild-based builder." The framework-agnostic core (`@softarc/native-federation`) worked cleanly for React throughout every phase of this migration; swapping federation runtimes now would be a high-risk rewrite for no functional gain.

## Where the durable detail lives

Every real gotcha found during this migration — the JSX transform split, the widget-loader Context `external`-array bug, the `scds-card` shadow-DOM lesson, the native import-map/`shimMode` fix, and more — is documented in full in `mfe-pot-platform/CLAUDE.md` (the shared architecture reference) and each app repo's own `CLAUDE.md` (repo-specific detail). This doc captures the narrative and the decisions; those files capture the "how it works" that a future contributor actually needs day to day.
